# Agents — entry protocol

> Lemony harness · vendor `0.11.0` · target `claude-code`.
> Generated by `lemony install` at `.claude/agents/entry-protocol.md`; safe to edit.
> Delivered to the main session only, by the `entry-protocol.sh` SessionStart hook.

This is the **dispatcher** the Orchestrator follows on every session. The
Orchestrator is the single human-facing hat; it invokes sub-agents (Spec Author,
Implementer, Reviewer, and the on-demand Architect / UI Designer) with fresh context
via the Task tool. Full role rules live in `.claude/agents/<role>.md`; skills in
`.claude/skills/`; task state in `.claude/state/`.

## Mode dispatcher

Parse the intent of the first prompt (or honor an explicit slash command):

| Intent signal | Mode |
| --- | --- |
| "continue", "resume", "pick up" + a `#id` or name | **RESUME** |
| "define", "new task", "I have an idea", "I want to build" | **DEFINE** |
| "bug", "error in", "it's broken", "fails when" | **TRIAGE** |
| a bare greeting / orientation question / nothing | **ORIENT** |

If the intent is ambiguous **between harness modes**, ask **one** disambiguation
question, then proceed. A concrete **non-harness** request is just answered — don't
surface the menu.

- **DEFINE** — the L1 full-SDD round-trip (see below).
- **RESUME** — first, an `in-progress`, `in-review` or `paused-for-clarification` task
  is routed by its task PR (found with
  `gh pr list --state all --search "head:harness/<id>-"`), before any checkout: merged →
  no task branch to check out, run [`task-closeout`](.claude/skills/task-closeout/SKILL.md) (retry-safe; a paused one resolves its
  discovery first); closed unmerged → offer resume / abandon / leave it; no PR on an
  `in-review` task → ask the human for its number. Then, for an SDD
  task, or an L2 task once it has left `pending`, `git fetch` and check out
  `harness/<id>-<slug>` before reading any state (the task state, and an SDD task's spec,
  live only on the branch until merge), then reload `.claude/state/tasks/<id>/` and
  continue from `progress.md`. An issue carrying
  `harness:partition-plan` is a partition parent, not a task — start its next part per
  `.claude/agents/partition.md`.
  Before acting on the task, read `.claude/agents/orchestrator.md` §"Dispatch" → RESUME
  (the routing per status — a pending stub, closeout-pending, a parked design, a pause —
  is not summarized here), and orchestrator §"Approval gate" for a `spec-ready` pickup.
- **TRIAGE** — the L2 lightweight path: read `.claude/agents/triage.md` and run it (see below).
- **ORIENT** — an intentless entry (greeting / "what should I pick up?" / nothing).
  Render the **dispatch menu**: the parked queue (the same listing `/resume` runs with
  no args — including the **`/spinoff` pending stubs**) plus the start options `/define`
  and `/triage`, and ask which to do. The start options are **unconditional** — an empty
  queue still renders the menu with just them. Best-effort and offline-safe: if `gh` is
  absent or unauthenticated, skip the listing and still offer the start options — never
  block.
  Authority + the full guard: `.claude/agents/orchestrator.md` §"Dispatch" → ORIENT.

A request for the **Architect**'s work — record an ADR, capture how the project does
something, change a convention, import documentation — is dispatched to the Architect
(Task tool, fresh context) as `.claude/agents/orchestrator.md` §"Architect (on-demand)"
says; never run its skills in this session.

## Task-fit dial

The harness is a dial, not on/off:

- **L1 — full SDD**: real features. Grill → spec → human gate → implement → review.
- **L2 — lightweight**: small bugs. Issue + state + implement (TDD) + light review.
- **L3 — bypass**: typos, mechanical renames, lockfile bumps. No issue, no review.

A task deserves the harness if it is **specifiable**, **verifiable**, or
**reviewable** (≥1). If none → L3. When in doubt, keep it in the harness.

## L1 round-trip (DEFINE)

A map of the steps. Before the step you enter at — step 1 for a new task, the step a
RESUME or a `/clear` lands on — and again after a compaction, read
`.claude/agents/orchestrator.md` §"L1 full-SDD round-trip (DEFINE)" and the section of
that step, and run it from there: the full rules for each step's labels and commands are there.

1. **Grill** — [`grill-with-docs`](.claude/skills/grill-with-docs/SKILL.md) → a PRD; separable wants → the partition question (`.claude/agents/partition.md`).
2. **Open the task** — the issue (`harness:managed` + `harness:sdd` + `harness:status:spec-in-progress`) and the branch `harness/<id>-<slug>`; nothing touches the default branch until the merge gate.
3. **UI design** — only if the task touches UI (`.claude/agents/ui-design.md`).
4. **Spec** — Spec Author: [`prd-to-spec`](.claude/skills/prd-to-spec/SKILL.md), then [`spec-to-issue`](.claude/skills/spec-to-issue/SKILL.md).
5. **Spec-ready + handoff** — flip to `harness:status:spec-ready`, commit and push the task state; ask: implement now or hand off?
6. **Approval gate** — present the spec cover (`.claude/hooks/lib/lemony.sh spec-cover --task-id=<id>`, verbatim); the human approves, and after the mode and auto-commit answers you flip to `harness:status:in-progress`; never self-approve (orchestrator §"Approval gate").
7. **Implement** — Implementer, [`tdd`](.claude/skills/tdd/SKILL.md); mode and auto-commit are set at the gate (orchestrator §"Implementation mode"; a step-by-step resume re-enters at its step log, orchestrator §"Step-by-step implementation").
8. **Review** — flip to `harness:status:in-review`, open the PR (`Closes #<id>`); Reviewer, full pass — it owes its own review passes, so the prompt names none (+ the UI Designer if it touched UI). The APPROVE's evidence ledger is validated by a script (`lemony review-ledger validate`), never by an agent.
9. **Merge gate** — never auto-merge; an authorized merge runs through `.claude/hooks/lib/merge-pr.sh <pr> --approve-issue <id> --squash`, which checks the APPROVE still matches the content (orchestrator §"Merge gate").
10. **Closeout** — [`task-closeout`](.claude/skills/task-closeout/SKILL.md) (orchestrator §"Closeout").

## L2 round-trip (TRIAGE)

Read `.claude/agents/triage.md` (again after a compaction) and run it: triage ([`triage-issue`](.claude/skills/triage-issue/SKILL.md)) → branch +
scaffold → implement ([`tdd`](.claude/skills/tdd/SKILL.md)) → review (the Reviewer's full pass) → the same merge gate as L1,
never auto-merged → closeout ([`task-closeout`](.claude/skills/task-closeout/SKILL.md)).

## Discovery interrupts

At any step, a sub-agent that hits a T1–T6 case (contradiction, unspecified decision,
scope drift, existing solution, infeasibility, convention conflict) **pauses instead of
guessing**: it runs [`raise-discovery`](.claude/skills/raise-discovery/SKILL.md), writing `tasks/<id>/discoveries.md` and
returning a one-line summary. The Orchestrator then runs [`resolve-discovery`](.claude/skills/resolve-discovery/SKILL.md) — the
task moves to `harness:status:paused-for-clarification` (+ `harness:discovery:T*`), the
human arbitrates, the owning agent updates its artifact, and the paused sub-agent
resumes. No discovery may remain unresolved at closeout. Details in
`.claude/agents/*.md`.
